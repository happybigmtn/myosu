# myosu — CEO Testnet Roadmap (CEO-SIGNED 2026-06-03)
Testnet north star: A named multi-node Myosu testnet where miners submit strategy, two validators score it identically, emissions flow by measured quality, and a human/agent reads a solved hand through the same gameplay surface against that live chain.
signed_off: true  (CEO sign-off 2026-06-03)

## Goals (sequenced now -> testnet)
- [medium] Real testnet genesis that provisions the subnet — Today `finney_testnet_config` (node/src/chain_spec/testnet.rs, 26 lines) reuses `localnet_genesis` which passes `game_solver: None`. A testnet deploy boots with NO subnet 7, no registered owner, no emission bootstrap, so the operator loop cannot run. Devnet is the only spec that wires the full game-solver genesis.
  - proof: `cargo run -p myosu-chain -- build-spec --chain testnet --raw` emits a spec whose genesis contains subnet 7, a subnet owner, and staking pools (parity with devnet).
  - proof: a fresh node booted from the testnet spec answers `gameSolver` RPC with `SubnetworkN(7) > 0` at block 1.
- [medium] Multi-node + dual-validator determinism on a shared network — The compose loop is one authority + one miner + one validator on one host. INV-003 (S0) requires two validators to score the same miner within epsilon, but it is currently only exercised in the single-process stage0 smoke.
  - proof: a 2-authority + 1-miner + 2-validator topology (separate processes/containers) reaches finalized blocks and both validators submit weights for the same miner with divergence < epsilon.
  - proof: emission accounting closes the exact integer budget on the multi-node run (ADR 011 contract holds off the single-process path).
- [long] Externally-verifiable read surface — A human/agent fetches a solved result (policy bundle / hand transcript with provenance) from the live testnet over a persistent endpoint, not a local subprocess smoke.
  - proof: `myosu-play` (or a thin RPC reader) connects to the testnet WS endpoint, plays one poker hand against the emitted strategy, and prints the bundle hash + miner UID + emission that backed the advice.

## Lens verdicts
CEO: Testnet is the right north star and myosu is the closest chain repo to it — the full miner→validator→emission→gameplay loop is already proven, just single-host. The highest-leverage de-risking proof points for the whole ecosystem are (1) a real provisioned testnet genesis and (2) dual-validator determinism, because every downstream Bitino integration assumes "a promoted bundle came from a quality-scored, emission-backed miner on a real network." Recent docs-only churn (reverted SEC table) is wasted motion; the next real slices are chain-spec and network-topology code.
Design: A credible public testnet demo must let a human/agent TOUCH a solved result over a persistent endpoint and SEE its provenance (bundle hash, miner UID, the emission that backed it). Today every read path is a local subprocess smoke. The P0 live-read mode is the design proof: same gameplay surface, real chain, verifiable receipt.
Eng: The blocker is concrete and bounded: `testnet.rs` is a hollow stub that omits the game-solver genesis patch, so any testnet boot has no subnet. The fix is factoring the existing, working devnet provisioning into a shared builder — low novel risk, high payoff. Multi-validator determinism is the second real slice; the code paths exist (devnet endows validator-2) but are never run concurrently. The promotion-ledger lane (PROMOTE-001) is blocked on an external artifact and is orthogonal to testnet — do not let it gate the network milestone.
## Sequencing & risks
Reconciliation: all three lenses converge on "the chain loop is proven local; testnet = make it real on a shared, persistent, multi-validator network." CEO and Eng agree the promotion/NLHE lane (currently the root IMPLEMENTATION_PLAN's "Priority Work") is real product work but is NOT on the testnet critical path and is externally blocked — so testnet proceeds in parallel and is not held by it. Design's live-read requirement is sequenced last because it depends on the persistent testnet endpoint (P0 #4) existing first.
Key risks: (1) refactoring devnet genesis into a shared builder could regress the working devnet compose proof — mitigate by keeping devnet's existing test green as the regression gate. (2) Dual-validator determinism may surface a real INV-003 epsilon violation under concurrency that the single-process smoke hides — that is exactly the bug testnet must flush out, so treat a failure here as a finding, not a blocker to defer. (3) Substrate multi-node networking (libp2p bootnodes, Aura/GRANDPA across processes) is the highest unknown; the compose path de-risks it incrementally before any cloud deploy.
